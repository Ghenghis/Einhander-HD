Dispatch Gates (the performance-critical path)

A PC reaching overlay_loader_dispatch is checked in order — every gate failure means interpreter time (the stutter source):

  1. overlay_cache_window_contains(phys) — is this address even candidate-eligible?
  2. Exact-entry candidate: generation-sum or CRC validates live RAM bytes.
  3. CPS continuation range: function entered mid-body still recognized.
  4. device_touch — function wrote MMIO; must interpret for accuracy.
  5. Shadow-diff — optional byte-diff validation; kernel <0x10000 excluded from want_diff.
  6. Native-exec gate + ranking — s_native_exec, overlay_native_blocked.
  7. Pass → call the DLL; any fail → dirty_ram_interp (counters accumulate).

Memory Model

0x00000000 – 0x00007FFF   kernel window      — unconditional candidate-eligible
0x00010000 – FLOOR        main-EXE text      — eligible only when dirty (overlay overwrote boot text)
FLOOR+      – 0x001FFFFF  overlay region     — unconditional candidate-eligible
0x1F000000+               MMIO / I-cache     — never code for dispatch purposes

OVERLAY_REGION_FLOOR and DIRTY_RAM_KERNEL_WINDOW_END in dirty_ram_interp.h. Clean boot text is deliberately excluded — it runs compiled; capturing it would violate the static-first design.

FMV Path

CdRead STR sectors → MDEC hw decode → 24-bit RGB frame (~320×192)
  → gl_renderer_present CPU path → upload_present_tex → PRESENT_FS quad
  → [fmv_filter mode: nearest|bilinear|sharp|bicubic|hd*] → window

*hd mode is the in-progress Tier-1 upgrade — see FMV SOTA plan. The true 1080p path replaces pixels upstream of present via the playback-substitution design in that doc.
