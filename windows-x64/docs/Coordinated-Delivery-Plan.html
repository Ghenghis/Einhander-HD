Detailed artwork that survives gameplay motion

Use the RTX 3090 Ti as a measured production resource

Inspect actual GPU memory, drivers, active workers, ComfyUI endpoint/queue, installed models and custom nodes. Reuse validated local models first. Benchmark one representative mapped facade and one mixed sign/lettering region. Retain each API graph, model filename/hash, seed, sampler/steps, guidance, denoise, source/crop dimensions, authoring/output dimensions and elapsed/peak-memory measurements. Choose batch size and tile overlap from observed memory rather than a card-name assumption.

Author structure, materials, warm/cool window lighting, facade relief, rooftop beacons and restrained glow in separate controlled regions. Generate illustrative content; rebuild exact lettering with source-grounded vectors or glyphs. Work in linear source bounds and preserve protected neighbors, UV layout, black STP texels, categorical transparency and palette animation. A generated concept becomes a texture only after mapped packing and real replacement draw proof.

Measure movement before deciding the detail scale

For each foreground, middle and distant layer, measure screen displacement between actual rendered frames. At presentation rate F frames/s and layer speed v pixels/s, displacement is d = v / F pixels/frame. At 600 pixels/s and 60 Hz, the layer moves 10 pixels/frame; this is an illustrative calculation, not a measured game speed.

A feature with on-screen width w pixels remains beneath a fixed screen point for about w / v seconds. Texture resolution cannot eliminate the display's persistence or make a tiny fast glyph readable. Preserve larger coherent material forms, enough edge contrast, stable outlines and valid filtering/mip behavior; reduce high-frequency shimmer and excessive sharpening. Review the actual scrolling sign at intended display scale and refresh rate.

  • Record actual output and viewport dimensions. Preserve 4:3: a 2160-line gameplay viewport is 2880×2160, which may sit within a 3840×2160 output.
  • Review stock and candidate at matched routes/poses, bright and dark exposure, native display size and 2160-line export. A resized small master must retain its true authoring resolution in provenance.
  • Capture complete palette/blink/window/beacon sequences; a CLUT count is not an ordered animation. Check frame-to-frame seams, STP blending, flicker and layer order.
  • Keep GPU authoring separate from performance runs. Record frame-time p50/p95/p99/max, presentation FPS, audio underruns, render settings, capture overhead and sample duration.
  • Set a 60 Hz target of 16.67 ms/frame, then report whether the final tested route meets it. A successful short menu sample cannot establish full-game 60 FPS.
