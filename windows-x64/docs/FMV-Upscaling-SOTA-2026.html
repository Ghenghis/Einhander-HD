Tier 1 — In-Shader Reconstruction (today)

Mechanism

The CPU-present path renders FMV frames as a 320×192-class RGB texture through a single full-screen pass (PRESENT_FS, gpu_gl_renderer.c:886). Four modes exist (nearest, bilinear, sharp, bicubic); the active one is bicubic (Catmull-Rom, 9 bilinear taps).

The upgrade adds a fifth mode "hd" that combines:

  • Lanczos-3 kernel resampling — 6×6-tap windowed-sinc reconstruction; measurably sharper than Catmull-Rom at the same smoothness, with no aliasing when scaling ≥4×.
  • RCAS-style adaptive sharpening — a light unsharp mask applied only where local contrast is low (protects smooth gradients from noise amplification).
  • De-banding dither — ordered blue-noise/ordered-matrix dither in the output write to break up the 8×8-block banding STR leaves in gradients.

Tier 2 — De-band & Denoise add-on

Ships inside the same u_sharp==3 shader as a second small branch or uniform flag. The dither step is 8 lines of GLSL (Bayer 8×8 or interleaved-gradient noise); a luma-adaptive smoothing pass is a second small draw or a folding loop.

Tier 3 — True HD: AI-Reconstructed FMV (the 1080p/1440p path)

SOTA GOAL The only route to genuine HD. Three phases, each separately verifiable.

Phase A — STR extraction & inventory

  • Locate every .STR video stream on the Einhänder disc image (D:\Games\Einhander\ROM\Einhander (USA).bin). Use jpsxdec (the standard PSX-STR extractor) or the project's own psx_libchdr-based tools to dump each movie sector-perfectly as uncompressed frames + XA audio.
  • Build an inventory table: STR id → sector range → frame count → fps → resolution → duration. Einhänder has ~7–9 FMV sequences (intro, chapter transitions, ending, staff roll).
  • Deliverable: fmv_inventory.json + lossless frame dumps per video.

Pipeline per video: frames → denoise (mild, preserves grain) → 4× Real-ESRGAN/Real-CUGAN → optional RIFE frame-rate double (15→30) → encode H.265 CRF ~18 at 1920×1080 (or 2560×1440) → mux original XA-derived audio untouched.

Output: one HD file per STR, e.g. hd_fmv\INTRO_1080p.mp4, plus a mapping file hd_fmv_map.json.

Phase C — Playback substitution

The emulator currently decodes each STR sector-by-sector through the MDEC block. To play the HD file instead, add a substitution layer:

  1. Detect STR start. When the game issues a CdlReadS/CdInt2 streaming read into an STR sector range (from the Phase-A inventory), flag "FMV n starting".
  2. Attach. Launch the corresponding pre-encoded HD file on a media pipeline (FFmpeg decode → GL texture, or libmpv/SDL_render). Keep the guest audio path: either let the emulator keep the XA audio (most robust — A/V sync is the game's own timing) or mux the XA track into the HD file and mute SPU during FMV.
  3. Sync. Match the file's play rate to the STR's nominal fps; on the game's "FMV end" sector read or timeout, cut back to normal scanout. A fade in/out hides seams.
  4. Fallback. If the HD file is missing/unloadable, fall back to the existing MDEC+shader path — the substitution is strictly additive.

What "SOTA 2026" Actually Looks Like

The genuinely-current ceiling for low-res game cutscenes is:

  • Upscaler: Real-CUGAN pro / Real-ESRGAN AnimeVideo or Topaz's Aion/Proteus models — all produce convincing 1080p/1440p from 240p-class sources.
  • Frame-rate: RIFE v4.x (optical-flow interpolation) → the 15 fps STR becomes 30 fps with real motion, not motion blur.
  • Grain: keep a light film-grain overlay post-upscale (prevents the "AI smooth" look).
  • Presentation: 4:3 pillarboxed at integer scale, or a mild 16:9 reframe if there's a widescreen-safe variant of the video.

That combination — extracted STR → AI upscale → interpolated → HD-substituted playback — is the same approach the DuckStation/PCSX communities use for "HD FMV mods". It is the realistic ceiling; nothing closer to "re-rendered" exists short of a studio remake.

Risks

  • A/V drift — mitigated by keeping the emulator's XA audio authoritative; the HD video only replaces pixels.
  • STR not cleanly extractable — some games interleave FMV audio/video in custom container; jpsxdec + a hex sanity check answers this in Phase A.
  • Perf during substitution — FFmpeg decode of a 1080p H.265 is cheap; but the GL texture upload must not stall the main loop — decode on a side thread.
  • License / tooling — Topaz is paid; the free path (Video2X/RIFE/Real-ESRGAN) is sufficient.

Decision

Implement Tier 1+2 now (measurable improvement today, in-code, reversible). Proceed to Tier 3 as a tracked project with Phase A as the immediate next step — it produces the inventory that makes every later choice concrete.
