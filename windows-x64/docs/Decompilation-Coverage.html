Analyzer

psxrecomp-analyze (sources in psxrecomp\recompiler\src\: main_analyze.cpp, analysis_db.cpp, analysis_export.cpp, bios_call_names.cpp) is a static-only tool — no trace import, no overlay capture feedback. Documented in psxrecomp\docs\FUNCTION_DISCOVERY.md.

Known Coverage Numbers

Static coverage gap (NOT filled from any runtime source):
  132 indirect transfer(s) have no proven target set.
  255504 bytes (40.1%) of the image belong to no code function.

IMPORTANT The 40.1% figure is unknown bytes, not "undiscovered code". It contains some mix of:

  • Raw data / assets baked into the EXE (lookup tables, vertex data, strings, embedded resources)
  • Unreachable code — branches reachable only via unresolved indirect transfers (132 sites)
  • Overlay staging / dead regions — bytes reserved or overwritten by RAM-streamed code
  • Alignment / padding between sections

Nothing so far has classified which is which. That classification is the pending work item.

What "Complete" Requires

  1. Build the analyzer — it is not yet built in build-ss8c: 
    cmake --build build-ss8c --target psxrecomp-analyze
psxrecomp-analyze disc\SCUS_942.43 --out analysis --emit-tsv analysis\functions.tsv
  2. Classify the gap — intersect discovered-function ranges with the image map:
    • blocks inside known data sections → data
    • blocks that decode cleanly as MIPS and end in jr $ra → code candidates
    • blocks targeted by overlay load addresses → overlay staging
    • remainder → dead/padding
  3. Resolve the 132 indirect transfers — jump-table recovery (recover_jump_table() in function_analysis.cpp) plus captured executed-PC data from overlay sessions.
  4. Overlay coverage — see Overlay-Pipeline.html; code streamed to RAM is invisible to static analysis until captured.
