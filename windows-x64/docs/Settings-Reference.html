Precedence

game.toml  <  settings.toml (user overrides)  <  command line

The launcher writes settings.toml. Hand edits are safe — but values outside the parser's accepted range are silently dropped (that was the supersampling bug).

Parser Behavior — Why Range Errors Were Silent

GOTCHA User settings parse via try_get wrappers in config_loader.cpp — an out-of-range value is skipped, leaving has_<key> false and the runtime on its default. There is no warning in the log.

Verify a setting applied by reading the startup log (e.g. supersampling Nx), never by trusting the file.
