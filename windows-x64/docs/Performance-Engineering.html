How the Interpreter Gets Off the Critical Path

The dirty-RAM interpreter exists to run code that a static shard can't cover (overlays, self-modifying code, runtime-generated dispatch paths). Two mechanisms decide whether a PC runs native or interpreted:

// overlay_loader.c — dispatch gates, in order:
//   exact-entry candidate  →  CPS continuation range  →  live-code validity
//   →  device-touch gate   →  shadow-diff gate        →  native-exec gate
// Any gate failure falls back to dirty_ram_interp (the stutter source).

Hot interpreter PCs are reported by the dirty_ram per-PC counters. Highest historical contributors: 0x173C8 (~6.8M insns/8s window), 0x13400 (~726k), kernel interior 0x4554–0x48E0.

The kernel RAM shard package (cap_kernlo2.json, 204 seeds across 0x80000080–0x80007003) compiled to 41 successful native DLL shards + 1 failed. After install, dispatch through those regions reported native on probe paths — but this does not prove every interior-walk dispatch is native; a residual interpreter share remains under audit.

Cache-Window Semantics

overlay_cache_window_contains(phys) decides what is even eligible for overlay-candidate dispatch:

return phys < DIRTY_RAM_KERNEL_WINDOW_END   // unconditional: low kernel
    || phys >= OVERLAY_REGION_FLOOR          // unconditional: overlay region
    || dirty_ram_is_dirty(phys);             // main-EXE text only if page dirty

Implication: clean boot text never enters the window — it always runs compiled (static-first design). Main-EXE text between the kernel window and the overlay floor becomes eligible only after a gameplay overlay dirties the page — i.e. once an overlay has written over the boot text, the bytes there are runtime overlay code.

Knob-Isolation Plan

To attribute the smoothness improvement and confirm each knob's cost honestly:

  1. Restart with rewind_depth=50, spu_hq=true, hd_textures=true (baseline stutter config).
  2. Re-enable rewind only → sample insns/sec + frame-time.
  3. Re-enable spu_hq only → same sample.
  4. Re-enable hd_textures only → same sample.
  5. Report the delta each knob produces in the same game phase.

This produces the real cost-per-feature table instead of "all three off = smooth".

Tooling Used

  • debug_server TCP endpoint 127.0.0.1:4370 — read_ram, heartbeat, per-PC interpreter counters, overlay loader status, CPS probes.
  • psxrecomp\tools\compile_overlays.py — capture JSON → native DLL shards.
  • build-release\cap_kern*.json — synthetic captures covering the kernel window.
  • build-release\ram_full.hex/.bin — full 2 MiB RAM dump for game-text capture mining.
  • docs\DEBUG_FINDINGS.md — running diagnostic notes.
