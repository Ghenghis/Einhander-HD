## Engine and Remix implementation

The current OpenGL renderer submits screen-space geometry with flattened depth. The texture workflow successfully ingested and decoded one DDS; no connected gameplay Remix project, ray-traced game render or DLSS gameplay path has been verified. NVIDIA documents a Direct3D9-oriented compatibility path. The current OpenGL stream does not directly provide the scene Remix needs. See [NVIDIA compatibility](https://docs.omniverse.nvidia.com/kit/docs/rtx_remix/latest/docs/introduction/intro-compatibility.html) and [actual setup results](RTX-REMIX-SETUP-20261114.md).

1. Preserve real GTE transform/projection provenance before flattening: model/view coordinates, transform identity, depth, projection parameters and exact guest-word provenance through FIFO/register/memory copies. Build an optional, disabled-by-default path with stale-overwrite, saturation, suppression and timeline tests. Do not infer world coordinates from screen positions alone.
2. Establish camera/object separation, stable mesh/material identities and submitted geometry coverage. Preserve native GPU ordering, transparency/STP, masks, feedback/copies and animated palettes. Classify HUD, sprites and particles separately. A view-space inspection capture is a foundation result, not completed world reconstruction.
3. Implement the compatible scene submission/backend bridge. The installed renderer's direct C API initialization now passes with official header 0.6.11; assess this resource/camera submission path first, including external presentation interop, before committing to a full D3D9 backend. Obtain an actual gameplay capture, open it in Remix, create the project and author keyed replacements. Reload and prove replacements persist through game boot and scene changes. An API-table probe, sample scene or dummy capture does not pass the gameplay gate.
4. Author physically based albedo, normals, roughness, metalness and emissive maps with stable scale and material ownership. Add scene lights and verify neon illumination, ship/weapon highlights, shadows, reflections, indirect lighting and volumetrics. Existing color/detail channels are not full PBR lighting.
5. Integrate supported temporal reconstruction/upscaling with correct depth, camera, motion, jitter, exposure and disocclusion handling. Validate thin neon strokes, fast bullets, explosions, smoke, moving ships and HUD composition for ghosting and flicker. Add supported latency controls and verify responsiveness in gameplay.
6. Expose implemented graphics options in the launcher and in-game menus: output/render resolution, supported reconstruction/AA modes, ray-tracing quality, texture/VRAM quality, particles/effects and relevant accessibility/readability controls. Verify settings persistence and hardware detection. No control may claim an unimplemented backend capability.

The RTX 3090 Ti target can use DLSS Super Resolution, DLAA and Ray Reconstruction when correctly integrated. NVIDIA Frame Generation requires RTX 40/50 hardware; Multi Frame Generation and DLSS 5's 3D-guided rendering target RTX 50. Those options require capability detection and testing on supported hardware. [NVIDIA's current feature matrix](https://www.nvidia.com/en-us/geforce/technologies/dlss/) documents these hardware limits. Check the installed Remix runtime's actual feature set too: a feature on NVIDIA's general page does not establish availability in this toolkit/runtime.
