Einhänder HD: master action plan

From stage 1 acceptance to all seven stages, endings and extras. Drafted 2026-11-13 by the Claude coordinator for review by the user and Codex. Status reflects what has been measured. Items that are planned or unverified are marked as such.

Where we are (observations, 2026-11-13; single runs unless stated)
  • Smoothness: observations only, not acceptance.
    • Native textures: one assisted, no-fire stage 1 run gave 60.008 fps with zero starved samples. This does not show sustained normal gameplay or full-game acceptance.
    • HD-on runs on the same day ranged from about 47 to 59.9 fps. The idle diagnostic gave 57.36. Most of them had audio starvation.
    • HD draw batching (PSXRECOMP_HD_OPAQUE_BATCH=1): one ordered off/on pair gave 49.4 vs 55.9 fps. That pair does not prove a speed gain.
    • Batching is off in Play-HD.cmd. Promoting it to default is a proposal, pending correctness and acceptance gates.
    • Run-to-run variance has not been characterised statistically, so decisions need repeated runs.
  • Sampler contexts, phase_profile in one slow window. These are sampled contexts, not exact costs or pure GPU time.
    • The interpreter context is about 39% and the GPU-processing context about 34%.
    • The "native" context (about 26%) is dominated by the game's VSync wait at 0x8001303C, which includes frame-end host work.
  • Audio evidence (v41 idle run).
    • The bracketing counters show 8,201 starved out of 488,160 callback frames.
    • The process capture shows one 90 ms observer gap (4,320 zero-filled frames) and four separate likely engine dropouts.
    • Alignment between the process and callback recordings is not yet established: whole-window correlation was 0.173.
  • Stage 1 art.
    • 31 of 85 key families are HD in the live pack.
    • Import plan v3 adds 635 rows that are built and class-validated (1,769 files, 0 mismatches).
    • Drache and 8 remaining families are in progress; 16 families need capture.
  • Stages 2–7.
    • Stage 2 was entered once in a research run with an invincibility aid, and 9 post-Drache (stage 2) keys have native sources from it. Nothing beyond that has been captured.
    • There is no mid-game save. The US disc's debug menu is a stub, and the hidden stage select is disabled in US code.
    • A continuous capture run is therefore the route in.
  • Robin has not yet killed the Greif. It sees enemies only through textured draws, so untextured beams and bullets are invisible to it.

Principles

  • Smoothness first. No visual or audio feature ships if it adds stutter or audio dropouts.
  • Faithful remaster. HD textures are class-exact to the native alpha at every texel centre. Never invent text or glyphs, and never recolour palettes. Audio keeps the composition, timing and loop points.
  • Acceptance stays honest. Each stage's final run is played by Robin with pad input only: no invincibility, no RAM writes, no cheats. Capture-only runs may use a clearly labelled invincibility aid and never count as acceptance.
  • Everything is reproducible. Frozen deliveries carry manifests and hashes, every runtime change carries a regression test, and every decision is documented in HTML under docs/.

Phase 1: finish stage 1

1A. Smoothness (Codex runtime, Claude review and analysis)

  1. Proposal: HD opaque batching on by default. Not approved yet. It follows correctness checks and acceptance. Gates:
    • repeated alternating off/on pairs;
    • a framebuffer hash comparison at fixed stage 1 frames;
    • the batch regression in the real GL fixture (target name to be verified; it is a header included in the GL fixture, not a known CTest target);
    • visual checks of the Greif, emissive and palette-cycled draws.
    The skin-detail concern was refuted by two independent source proofs.
  2. Reduce GPU-processing cost. About 34% of sampled contexts; section 22 measured the HD draw handler at about 246 ms/s and about 185 ms/s of HD-on cost as untimed. Break down GP0 processing per step (key hashing, cache lookup, first-use decode/upload, CLUT handling, batch build). Then apply the top fixes: memoise keys per VRAM page and CLUT generation, skip re-hashing unchanged pages, and move decode off the emulation thread. analysis in progress
  3. Reduce interpreted code. About 39% of sampled contexts.
    • Integrate the CPS-unit validation fix (phase 2; v2 revision for virtual-PC aliases in progress). It lets non-leaf and continuation code qualify.
    • Then qualify the hot SYS.EXE loops (R1 0x3A998 is already qualified; next R2 0x3A6FC, R4 0xB5C80 and the rest of the section 18 list).
    • Then SYS-primary static compilation. Its isolated implementation and bootstrap tests are in progress.
  4. Rewind cadence fix. Ordinary gameplay is classified as a movie because of the XA music latch. The fix restores the user's gameplay target cadence (interval 15 frames, about 4/s) and keeps the movie target (about 15/s). These are target cadences when a safe snapshot succeeds; live runs show almost no successful snapshots, and the new counters are needed to measure them. Diff and tests are ready.
  5. Timing fix (published GTE/MULT timestamps) is kept. The effective-time shortcut was rejected because it changes device-service points.
  6. Measurement protocol: at least 3 alternating repeats per arm; game window foregrounded and untouched; manual quiet ACK; NVML logging.

1B. Art

  1. Import plan v3: 635 rows, class-exact. Codex imports it, then runs a live A/B. Decisions pending: 5 HUD duplicates, the HUD-fade CLUTs, and Astraea v2.1 (an optional set).
  2. Drache HD (W6, in progress) and the 8 native-but-sourced families (W6, in progress).
  3. The 16 capture-needed families come from the AQ-01 capture run (shared with phase 2).

1C. HD audio (opt-in, must not cost smoothness)

  1. Music and voice.
    • Bit-exact XA decode of every stream.
    • Super-resolution to 48 kHz and per-stem restoration via source separation.
    • Sample-accurate length and loop points.
    Models are downloaded from official sources with user approval. in progress
  2. Sound effects. Bit-exact SPU ADPCM decode, keyed by CRC32, with HD clean source samples and seamless loops. in progress
  3. Runtime audio pack (design for Codex): music replacement on an audio worker thread with fallback, SFX substitution feasibility, FLAC/Opus/PCM choice, and a 48 kHz output stage. in progress

1D. Robin v2 (stage 1 first)

  1. RAM-decoded world state, read-only: player, enemies, boss parts, bullets, beams, pickups and scroll. This removes the blind spot for untextured projectiles. design in progress
  2. Short-horizon threat prediction and a dodge planner over pad inputs. Weak-point targeting: the Greif's grey gun arm, then the mount; the Drache's head, then the eye. A pod pickup and switching policy.
  3. Offline scoring against recorded traces. Then live: Greif kill, Drache kill, full pad-only stage 1 clear.

1E. Menus, HUD, end states and the Dev Control Center

  1. An in-game options menu exposing the HD features: HD textures, batching, audio pack on/off, 48 kHz output, rewind, filtering. It uses original-style lettering and invents no text.
  2. Title, results/tally, game over, continue, ranking and name entry all in HD.
  3. Dev Control Center completion:
    • Robin v2 controls and its live world-state view;
    • quiet-window status;
    • the run/evidence browser;
    • HD pack import and validation;
    • audio pack toggle;
    • stage capture tools;
    • the performance dashboard (phase profile, starvation, NVML).

Phase 1D: stage 1 HD demo build

  • Scope: boot → title → stage 1 through the Drache and the tally → return to the title (or a "demo complete" screen built only from existing game lettering). All stage 1 HD art and audio, with smooth pacing.
  • Packaging: a versioned Windows build plus launcher. The runtime needs the user's own disc image and BIOS; no game data or BIOS is bundled in anything distributed.
  • Gate: phase 1 exit criterion.

Phase 2: acquisition of stages 2–7 (starts now)

  1. Capture-only continuous chain (Codex now, Claude after handoff): stock-first dumping, recorder windows per segment, and one Continue leg per stage, starting with AQ-01 (Drache, tally, stage 2 entry). Invincibility-only aid, labelled capture-only.
  2. Static extraction from the disc (in progress): decode BINPACK containers and any compression, validate on stage 1 keys, then predict stage 2–7 keys and native sources so authoring can start before live capture. An HD texture built on a static source is imported only after live capture confirms its key.
  3. Coverage (from the catalogue): 7 stages with their mid-bosses and bosses, branches, two endings, movies MOV01–06, credits, gallery, and the unlockables:
    • Schabe, EOS UFG Mk.IX;
    • the Juno, Flash, Mosquito and Python pods.

Risks

  • Codex budget runs out. Mitigation: phase 0 documentation now, and Claude takes over runtime and capture work after the handoff.
  • HD cost may not reach 60 fps through rendering fixes alone. Mitigation: interpreter reduction (CPS fix, SYS shards, SYS-primary) in parallel.
  • Static extraction may not match runtime keys (composed pages, palette cycling). Mitigation: the live capture chain remains the authority.
  • Measurement noise. Mitigation: repeats, foreground control and quiet windows.
