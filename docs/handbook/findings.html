Corrections and rejected explanations

  • Cross-series batching confound. Earlier normal2 controls enabled opaque batching; later v40 controls disabled it. This was initially missed and corrected publicly. Do not blame the entire difference on the clock fix, host load or GPU power state.
  • Dispatch-entry totals are not function cost. 0x26714 is a short epilogue; its attributed instructions include chained execution. Earlier 23–29% and large timing-gain estimates were withdrawn.
  • Actual PC samples. A 95-second histogram had 389,193 samples, zero drops. A later 120-second histogram filled the 8,192-bucket table and dropped about 1.1%; current capacity is 32,768. The face loop near 3A998 and unlit loop near 3A6FC are real interpreted hot regions. Instruction frequencies are not CPU-time shares.
  • Native 0x1303C attribution. The VSync loop contains frame-end host work. The slow ten-second sampler had roughly 39% interpreter, 34% GPU context, 26% native context. Those are observations of tagged contexts, not exact per-function cost.
  • Idle skip. Current game VSync wait stores a timeout counter, making it ineligible for the existing no-store rule. Enabling the guarded feature produced two boot skips and zero additional gameplay skips. No safety-rule widening or blind MMIO polling skip was applied.
  • GPU clocks. Read-only clocks varied. A P5 snapshot taken after a game exited is not evidence of in-game P5. No driver power/clock setting has been changed by this work.
  • Audio correction cap. A synthetic steady-rate case improved at 1%; real same-source gameplay did not resolve, and either cap still starved under an injected 300 ms stall. Increasing correction is not a substitute for fixing producer stalls.
  • Rewind. XA music incorrectly selects movie cadence, but almost no safe snapshot completed during the measured gameplay windows. The classifier bug is real; it does not establish that frequent successful rewind snapshots caused those stalls. The narrower classifier and actual capture counters are integrated in source commit 7be82c4. Live v43 gameplay recorded zero movie-classified frames over 6,686 frames, 2,732 attempts, one stored snapshot (2.716 ms serialization), and 2,731 unsafe-context refusals. Audio still starved.
  • Process audio. Earlier eight silence candidates matched bridge fade fingerprints by inference; their callback dump ended before capture. The latest overlap has a documented 90 ms observer hole and four separate bridge-signature dropouts. Independent sample alignment confirms the supplied 4,256-frame callback offset across 18 interior windows; 14 match within one PCM unit throughout. The observer hole has callback audio present. Localized peak differences remain; whole-device continuity is not established.

Open defects and next proof

  1. Producer starvation before/at boss and during firing: qualify alias-correct native hot code and isolate render work, then repeat ordinary combat and FMV with declared observers.
  2. CPS validator: one-unit boundaries reproduce/fix continuation artifacts, but canonicalizing the authoritative entry alias is not acceptable. Preserve virtual PC in routing and test escape cleanup before integration.
  3. SYS-primary: verify boot hash latch, title/RAM/framebuffer parity, mismatch fallback, code flips, restore/reset and identity. Never retarget SCUS text guards prematurely.
  4. Robin: fill perception gaps and demonstrate actual boss clears with ordinary pad input.
  5. Art/menus/later stages: integrate validated sources, resolve palette uncertainties, then verify every actual state and motion route.
