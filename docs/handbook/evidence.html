Quiet-window protocol

  1. Prepare a fresh candidate first; verify immutable parent and runtime hashes.
  2. Set CPU-QUIET and GPU-RESERVED, wait for no GPU holder and an empty ComfyUI queue, and obtain a fresh manual quiet ACK from Claude.
  3. Verify the prior owned game exited and its isolated debug port closed. Use a retained Popen identity and exact path, not a name-wide process kill.
  4. Launch the private game. Select its unique current window and foreground it during boot. Check fresh screenshots and related windows; an occluded dialog is not absent.
  5. After timing starts, avoid UI switching, builds, exports, hashing or directory scans. Record only the declared bounded observers.
  6. Capture after timing when possible. Stop the bounded aid and recorder, release input, close the owned game, retain exit/port/error proof.
  7. Release CPU/GPU markers promptly and tell Claude. Do not silently restart the rejected process-suspending central gate.

Receipts and decisions

Retain candidate.json, launch-candidate.json, copied executed scripts, command receipts, one-Hz observations, stdout/stderr and world-flypast-proof.json. Record CPU/GPU quiet acknowledgement and foreground observation separately. A foreground observation is not continuous focus logging.

Compare explicit settings, especially opaque batching, render preference, rewind cadence, staged native cache and emissive/world sampling. Different initial audio fill and guest-frame progress mean an ordered pair is not an identical replay. A higher average alone does not prove a causal win.

Actual audio

Host tap 2 is callback PCM. Absolute sample-frame indexes anchor exact WAV excerpts copied after measurement. The strict process-loopback helper accepts an explicit owned PID and expected image, includes only that tree, and allows at most one verified direct Windows system console-host child with stable PID/creation time/path. It rejects other descendants. It does not capture microphone or system-wide audio.

python remaster-audit/audio-evidence/process-loopback/analyze_capture.py PATH/TO/process-output-after-measurement.wav --json-out PATH/TO/analysis.json

Read WAV and timing sidecar together: observer gap fills, discontinuities and timestamp errors are separate from PCM silence candidates. The process device’s repeated device position is not a hardware-style clock; use validated QPC packet positions. Bracketing callback counters include helper setup/teardown, and weak envelope correlation cannot establish exact waveform alignment.
