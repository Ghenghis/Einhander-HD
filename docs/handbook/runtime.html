Runtime architecture

The Windows build combines generated static code, runtime overlay DLLs and an authoritative RAM interpreter. All three share the guest clock and device model.

Boot and executable identity

The retail entry file SCUS_942.43 loads cdrom:\SYS.EXE;1. Captured gameplay text matches SYS, not the original loader image. Current generated SCUS code must retain its SCUS byte guards. Changing the guard reference to SYS without regenerating the corresponding static code would admit incorrect code.

The separate SYS-primary proposal keeps disc/boot identity, cards and rewind identity stable, waits for a qualified entry plus a full SYS text hash before admitting static SYS code, preserves per-function byte checks and falls back on mismatches. It is under isolated implementation; it is not installed or accepted.

Dispatch and byte admission

windows-x64/psxrecomp/runtime/src/overlay_loader.c tracks loaded candidates, ranges, current CRC matches, native execution, comparison budgets and fail-closed state. windows-x64/psxrecomp/runtime/src/dirty_ram_interp.c interprets changed or unavailable RAM code and handles delay slots, nested calls and safe device-service boundaries.

Exact-entry diagnostic admission no longer lets a broader unverified owner mask a focused candidate. This selection change is restricted to differential mode; normal bundle preference and byte validation remain intact.

Cycles and causality

windows-x64/psxrecomp/runtime/src/psx_cycles.c owns published guest time, deferred charges and device deadlines. Completion timestamps must include pending charges. The accepted fix publishes time at the boundary; an unconditional “effective time” shortcut was rejected because it can defer device effects across an instruction boundary. Keep the device-deadline regression intact.

Rendering

Guest GP0 commands enter GPU processing, then native/HD rendering. HD admission uses captured source words and palette identity; replacement RGB and categorical alpha/STP remain separate. The opt-in opaque batch combines compatible HD submissions. Filter caching avoids repeated nearest/linear state calls. Bracket retention avoids redundant FBO transitions only inside a guarded native/HD or HD/HD handler gap.

The v41 retained-gap marker is not an “active batch” flag. A kept gap must be consumed before the handler returns. Wide mode, native-edge paths and incompatible native queues exclude retention. hr_kept_leaks must stay zero.

Audio

The guest SPU produces nominal 44.1 kHz audio; the host callback consumes device-rate PCM. windows-x64/psxrecomp/runtime/src/recomp_audio_drc.h supplies a persistent band-limited fractional resampler and bounded fill controller: target/prefill 180 ms, ring 280 ms, 32 taps, 75 ms low-pass, correction cap 1%, slew 0.75 percentage points/s. These are source defaults, not a guarantee against long producer stalls.

Starved sample frames are not a count of audible gaps. A callback PCM dump proves what the bridge emitted; process loopback observes Windows process output; neither proves physical-DAC continuity. Do not hide starvation by replacing music or retiming evidence.

Presentation and profiling

The frontend selects vsync ownership or wall pacing. It does not deliberately apply both by default. During measured slow periods the pacer slept almost zero. Native phase samples at 0x1303C include frame-end host work inside the game’s VSync wait, including present, debug polling, rewind and audio pumping. They are not pure native function cost.
