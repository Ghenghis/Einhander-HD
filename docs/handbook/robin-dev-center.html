Robin and Dev Center

Robin is a pad-input controller hosted by the local Python bridge. Its button being present does not prove its policy can perceive, aim at or avoid every enemy.

Service boundaries

windows-x64/tools/ein_bridge.py serves the local development UI, proxies one JSON-line command at a time to the game’s TCP debug server, and hosts Robin in a background thread. Bridge HTTP default is 8090; game TCP default is 4370, overrideable by EIN_DEBUG_PORT. windows-x64/tools/dev_center.js is browser UI code, not the HTTP server.

Endpoints include GET /health, GET /bot/status, POST /bot with start/stop/config, and attract/demo controls. Development tools can deliberately write catalogued values; the ordinary acceptance harness places a separate command boundary in front of that capability.

Perception and policy

Read-only native hull/draw tracking feeds stage and combat policies. Movement options include simple lanes/weaves and calibrated draw/combat lanes. Hull coordinates are craft- and viewport-specific; the Mk.II controller cannot simply be reused for Mk.III or Astraea. Earlier RAM-position guesses failed live qualification and must not be reintroduced as facts.

windows-x64/tools/robin_combat_policy.py prioritizes fresh textured targets and weak-point candidates. windows-x64/psxrecomp/runtime/src/threat_draw_tracker.h collects supported draw families; the latest source separates Greif arm/mount geometry from the generic boss body. Body parts are not automatically contact hazards, and disappearance is not proof of zero HP. Projectile evasion remains independent.

Untextured beams/bullets and missing Drache families remain perception gaps. “Visually aware” currently means bounded verified draw evidence, not universal image understanding. The proposed RAM-aware Robin v2 and dodge planner are design work, not a shipped controller.

Ordinary acceptance

remaster-audit/run_robin_stage1_acceptance.py uses verified native menu gates, private writable data, bounded pad decisions, no turbo, no invulnerability hold, no guest RAM writes and no state loads. It records observations and needs independent stage-clear review. --seconds bounds a run; a local STOP file ends it.

python remaster-audit/run_robin_stage1_acceptance.py --help

Explicitly use --supersampling 2 for the normal-resolution gate; the tool’s historical default is 9. The normal Robin UI route does not automatically adopt private harness flags or experimental rendering defaults. Validate the actual launcher button after promotion.

Remaining E2E routes

Require actual movement, firing that hits targets, evasion, weapon/pod behavior, Greif defeat, post-boss/Drache progression, death, Continue, Game Over, results, restart and user-data flows. A timer-assisted source run can acquire material, but it cannot satisfy these ordinary acceptance gates.

Computer-use recovery

Inspect current windows and fresh screenshots. An editor or secondary dialog may be behind another window or minimized. Bring the intended app forward before deciding a control is missing. Accessibility text can be stale; never reuse old element indexes or coordinates after a state change. Leave user drafts untouched.
